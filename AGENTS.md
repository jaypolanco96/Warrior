# Warrior project guidance

Read `docs/claude-context.md` for recovered decisions and evidence limits. Current source wins over historical reports. Work in Warrior, not the Oakland folder the IDE may open.

Preserve the distinct rainbow/Zulu six-agent trading desk, indaba, spotlight tour and mobile folding. The agents are tested rules, not chatbots. This is static browser modules plus Vercel functions; shared source is in `lib/`, with browser copies generated by build.

Keep practice/live accounting and learning separate, position-mode sales, pool/token/launch safety, rent-aware principal, measured receipts, reserve and risk limits, transfer-adjusted daily limits, write-offs and partial-sale repricing. Self-ruling may move only ADAPT dials and must preserve probation, undo and visible history. Auto-trading needs the browser open; service worker and wake lock do not replace a keeper. Warrior and Laugh do not coordinate a shared wallet.

For code edits run `npm test` and `npm run build`, completing build before browser suites. Use synthetic isolated storage and practice mode; never use real wallets, environment secrets or account journals as fixtures. Validate responsive/tour behavior when changing UI. No global check script exists.

Do not commit, push, deploy or move funds unless requested for that concrete action. Deployment uses GitHub pushes through the existing Vercel integration; never direct `vercel deploy` or relink. Check for concurrent edits and scheduled workflow commits before changing/synchronizing files. Do not automatically copy changes between Warrior and Laugh.
